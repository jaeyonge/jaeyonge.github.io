# Visit analytics

## Scope and configuration

The owner requested GA4 traffic, referral, section exposure/time and action measurements and supplied measurement ID `G-SH3WKZGQ93`. The public ID and executable thresholds live in [analytics.json](../content/analytics.json); they are not secrets. Never add an API secret, account credential, visitor identity or service-account key to public code.

[SiteLayout](../src/layouts/SiteLayout.astro) renders one consent component for production profile pages. [analytics.mjs](../src/lib/analytics.mjs) loads one async Google tag only after an analytics choice of Allow. It excludes the language gateway, print/compose pages, nonproduction hosts and automated browsers. GitHub Pages remains the host. Browser tests emulate the production origin but intercept all Google traffic; normal tests and PDF/social exports must never send real events.

The new controls use bilingual UI strings from YAML and existing tokens. The first-visit choice is nonmodal and does not block reading. Allow uses the shared blue primary-action style at the owner’s request; Decline retains a readable neutral button. Both choices keep equal dimensions, centered labels, 44px minimum height, visible keyboard focus and direct one-click access. Do not preselect consent or hide/degrade Decline. The footer's Analytics settings button reopens the choice; declining after allowing disables tracking, clears `_ga` cookies and reloads into a page without the tag. Preferences synchronize across tabs through storage events. With blocked local storage the choice works for the current page but cannot persist. With JavaScript disabled the site stays readable and analytics is off.

This is basic consent-gated collection, not advanced cookieless pings. Advertising storage, advertising user data and personalization are denied; Google signals and ad-personalization signals are disabled. Counts describe consenting, measurable visits, not all humans who saw the page. Ad blockers and failed transmissions can reduce coverage.

Only configured campaign query parameters with restricted characters are retained in the page URL. Other queries and fragments are removed; referrer is reduced to origin. UTM values are channel/campaign labels only—never use a recruiter's name, email, application ID or other personal identifier. Custom click events send a fixed target category or stable research ID, never email addresses, phone numbers, link text or unrestricted URLs. No user ID, session replay, fingerprinting or raw-IP report is implemented. Approximate geography and ordinary engagement data are GA4 features; analytics geography does not alter the site's language resolver.

## Measurement contract

| Event                   | Trigger / interpretation                                                                                                                                                                                                                                                 | Custom parameters                                                       |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------- |
| `page_view`             | Once when consent enables a tracked profile page; root redirects do not add another view. GA4 config suppresses automatic pageview and the implementation emits this event explicitly.                                                                                   | `page_language`, sanitized `page_location`, origin-only `page_referrer` |
| `section_view`          | Once per section per page load after meaningful viewport exposure for the configured continuous duration. A section can be reached via anchor navigation without reaching earlier sections.                                                                              | `section_id`, `page_language`                                           |
| `section_engagement`    | Incremental active-screen seconds, flushed on section changes, heartbeat, tab hiding or leaving. Only the most-visible qualifying section owns time so overlapping sections do not double-count duration. Background/unfocused time and bfcache suspension are excluded. | `section_id`, `visible_seconds`, `page_language`                        |
| `scroll_depth`          | First viewport-bottom crossing of 25/50/75/90% per page load. This is reach, not reading.                                                                                                                                                                                | `scroll_percent`, `page_language`                                       |
| `resume_download_click` | Click on the Korean or English PDF link; not a completed transfer or proof of reading. Direct PDF URLs are outside JS page tracking.                                                                                                                                     | `target_kind=pdf_ko/pdf_en`, `page_language`                            |
| `paper_click`           | Click on the linked paper for an existing research item.                                                                                                                                                                                                                 | `target_kind` = stable research ID, `page_language`                     |
| `contact_click`         | Email or phone link click, not message delivery.                                                                                                                                                                                                                         | `target_kind=email/phone`, `page_language`                              |
| `profile_link_click`    | Known LinkedIn, Scholar or GitHub profile link click.                                                                                                                                                                                                                    | `target_kind=linkedin/scholar/github`, `page_language`                  |

Section IDs: `about`, `experience`, `research`, `education`, `awards` (the last includes languages). A viewport exposure is at least the lesser of 120px, 20% of viewport height and 25% of the section height, excluding the fixed header. `section_view` considers all qualifying sections, while elapsed time belongs to the one with the largest visible height. Reaching several sections at once is valid and must not be forced into a sequential funnel. Fast passes shorter than the configured view duration do not emit `section_view`.

Visible seconds are **deltas**, not cumulative snapshots: sum them, do not sum a running total or interpret average heartbeat duration as average visit time. Flushing may lose the last event on abrupt process/network termination. The browser cannot establish reading, comprehension or attention, and it does not detect an idle person who leaves the window active.

## GA4 account setup after deployment

Code cannot create the owner's reports or confirm ingestion in an account it cannot access. In the supplied property's Admin:

1. Confirm the Web stream URL is `https://jaeyonge.github.io` and measurement ID matches the config. Korean/English share this stream.
2. Under Enhanced measurement, turn off automatic **Scrolls**, **Outbound clicks** and **File downloads** if using the custom events above; otherwise one action appears under both the automatic and custom event names. Do not add a second Google tag or a GTM copy of this tag. If automatic history page views are enabled, ensure they do not introduce duplicate pageviews when future client routing is added.
3. Create event-scoped custom dimensions: **Section ID** → `section_id`, **Page language** → `page_language`, **Target kind** → `target_kind`. For percent breakdown, register **Scroll percent** → `scroll_percent` if needed.
4. Create an event-scoped custom metric **Visible seconds** → `visible_seconds`, unit **Seconds**. This is a section exposure metric, distinct from GA4's built-in user engagement time.
5. Optionally mark `resume_download_click` and `contact_click` as key events. They indicate actions, not completed downloads/messages.
6. Visit a profile page, Allow analytics, move between sections and click a link; check Realtime. Use Tag Assistant/DebugView when debugging, without leaving a permanent `debug_mode` on public visitors. Regular custom reports may take 24–48 hours after registration to populate and are not retroactive.

## Useful reports

- **Section reach:** filter `event_name=section_view`; rows Section ID, columns Page language; metrics Total users and Event count. Users are GA4's deduplicated estimate; events are page-load-level exposures. Show reach against consenting profile visitors, not an unrelated all-site count.
- **Section exposure:** filter `event_name=section_engagement`; rows Section ID; sum Visible seconds. An average per reached user requires dividing this total by the matching section's reached-user count for the same period/segment, not the average per heartbeat event.
- **Sequential funnel:** Explore → Funnel exploration, user-sequence steps: `page_view`, then `section_view` with `section_id=about`, `experience`, `research`, `education`, `awards`. Keep steps indirectly followed (other events may intervene). Report it separately from independent section reach: direct research anchors legitimately skip earlier steps. GA4 funnel exploration is user-based and can span sessions; do not call its counts a same-visit funnel. For a strict session-level funnel, use an analysis grouped by GA4 session identifiers (for example in an authorized BigQuery export), and do not treat a time-between-steps limit as proof of one session.
- **Actions:** resume/paper/contact/profile events by target kind and language; compare source/medium, landing page and device categories. A PDF click is reachable in the hero, so it is not necessarily the final step after reading all sections.
- **Attribution:** use GA4 acquisition reports and consistently tagged generic campaign links, e.g. `?utm_source=linkedin&utm_medium=profile`. IP-derived countries/cities and inferred user counts are approximate, not personal identity.

## Verification and maintenance

Run `pnpm check`. Analytics tests use a mocked production origin with blocked Google transport, covering consent, exactly-one tag/pageview, safe URLs, no contact data, independent/deduplicated section reach, hidden-tab time exclusion, native downloads, storage failures and withdrawal. WebKit and Chromium both run the analytics tests. Inspect real light/dark mobile/tablet/desktop consent UI and verify print remains unaffected. Update this contract and tests with changes to measurement semantics; keep raw measurements and screenshots in ignored reviews.

Scrolling alone never grants consent, and interactions before Allow are not replayed as earlier section exposures.

To verify installation, open `https://jaeyonge.github.io/ko/` or `/en/` in a regular browser, select Allow (or reopen footer Analytics settings), then use Tag Assistant and the property's Realtime report. A successful script/request check does not prove account ingestion: confirm the matching Web stream and any account filters in GA4.
