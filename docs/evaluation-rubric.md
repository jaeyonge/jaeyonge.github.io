# Evaluation rubric

Use observable evidence, not an aggregate score that can conceal a factual, access, asset or build failure. The [guide map](guide-map.md) identifies each rule's owner; current website composition and PDF composition are separate contracts.

| Area                        | Acceptance evidence                                                                                                                                                                                                                                                                                                                                                       |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Facts and scope             | Claims trace to public-safe evidence/owner corrections; preserve dates, amounts/baselines, individual vs. team, measured vs. planned, duplicates vs. customer charges, percentages vs. percentage points. Apply [editorial decisions](editorial-decisions.md).                                                                                                            |
| Writing and naming          | Concrete problem, personal contribution and supported result; official full paper/venue names and source links; domain language remains natural without unnecessary parenthetical definitions. See [content guide](content-guide.md).                                                                                                                                     |
| Core strength               | Facts show business decisions, code/query/raw-data verification, reusable standards or automation; no invented impact to force every item into one narrative.                                                                                                                                                                                                             |
| Bilingual quality           | Meaning, status, scope, units and figures match; natural prose; counterpart reviewed per [translation guide](translation-guide.md).                                                                                                                                                                                                                                       |
| Source reuse                | Selected bullets render the exact authoritative YAML text/emphasis across web, print HTML and PDF. Different selections are configured, not alternate summaries or hardcoded prose. Trace each selected achievement by ID.                                                                                                                                                |
| Structure                   | Web follows the approved five-section order; PDF follows `outputs.pdf`. Three selected achievements per company/research, mandatory Gyeongnam education and paper links remain. No technology section.                                                                                                                                                                    |
| Emphasis                    | Review every selected bullet in both languages, first bold-only and then in full. Target/action form a complete contribution, delivered system and important outcomes are not lost, and attribution/qualification survive. Do not leave verbs alone, bold a functional inventory or effectively bold the whole sentence. See [emphasis guide](emphasis-guide.md).         |
| Alignment and spacing       | Institution, role and prose text axes match; logos occupy only the name row. Web dates stay with their role; PDF dates share the print right edge. No empty logo columns, filler rows, forced equal heights or unexplained accumulated footer gap. Long names and wrapped lines remain clear.                                                                             |
| Controls                    | Trigger/option styling is consistent, SVG chevrons are centered, selected state is perceivable, keyboard/focus/Escape/outside-click/selection behavior works, related popovers do not compete, and no-JS fallbacks remain usable.                                                                                                                                         |
| Assets and loading          | Committed assets decode and visibly paint, with correct per-brand themes/transparency/proportions. Test initial OS theme, manual override, return to system and OS changes; toggling a ready page must not expose an unloaded hidden logo or require another logo download. Enforce [asset rules](assets-guide.md) and validator budgets.                                 |
| Responsive/UI               | Required [viewport samples](responsive-guide.md), both languages/themes, long headings, keyboard, no-JS, reduced motion and delayed/failed assets/fonts checked. No overflow alone is insufficient: inspect clipped/overlapping controls and readable line lengths too.                                                                                                   |
| PDF                         | General profile is one A4 page per language, black text/links, correct fonts, justified bullets with final line left, common right date edge, exact selected prose, selectable text, real links, matching content hash/profile and no clipping/orphans. Current font sizes and exclusions are owned by [print guide](print-guide.md), not a separate three-page fallback. |
| Reproducibility             | Frozen dependencies, recorded reference revision, clean build without private `sources/`, no runtime local paths/remote logos, isolated production-server browser tests.                                                                                                                                                                                                  |
| Documentation and iteration | Owning guides, examples, current decisions and acceptance checks agree. Record actual defect → evidence/location → impact → fix → recheck under ignored reviews. Do not claim independent review, user comprehension gains or verification that did not occur.                                                                                                            |

If the one-page target conflicts with readable exact selected content, adjust layout within approved bounds or obtain an owner decision on shared content/selection. Do not silently summarize, drop selected bullets or reduce type below the print guide's current minimums. Changing the accepted target requires updating its owning guide and enforcement together.

Run checks appropriate to the change per [update workflow](update-workflow.md). Automated checks supplement visual review; neither establishes complete accessibility, ATS compatibility or future hiring outcomes. A historical plan or a passing score cannot override an observed regression.
