# 목적과 읽기 흐름에 따른 개인 프로필 구성

갱신: 2026-10-18. 이후 승인된 배치를 통합한 현재 구성 명세다. 폐기된 왼쪽 로고 도식이나 직무 우선 시안을 함께 활성 규칙으로 유지하지 않는다. 일반 원칙은 [디자인 가이드](design-guide.md), 매체별 PDF 구성은 [인쇄 가이드](print-guide.md), 검증은 [평가 기준](evaluation-rubric.md)을 따른다. 이 명세 자체가 독립 사용자 평가나 모든 환경의 검증을 뜻하지는 않는다.

## 독자의 질문과 중심 메시지

페이지는 누구인지, 어떤 일을 맡길 수 있는지, 실제 무엇을 판단하고 만들었는지, 어느 조직에서 어떤 역할로 일했는지, 연구에서 무엇을 기여했는지, 어떻게 확인·연락할 수 있는지에 답한다.

중심 메시지는 **비즈니스 문제를 이해하고, 코드·쿼리·데이터로 원인을 검증하며, 검증한 해결 방법을 재사용 가능한 기준과 자동화로 만드는 데이터 분석가**다. 소개에서 짧게 제시하고 경력·연구의 사실로 뒷받침한다. 모든 항목을 같은 성공 서사로 바꾸거나 전체 연구 결과를 개인 성과로 귀속하지 않는다.

웹 순서는 소개 → 경력(학교 근무 포함) → 연구 → 학력 → 수상 및 어학이다. 섹션 제목에는 장식용 번호를 붙이지 않는다. 회사별 세 성과, 연구별 세 불렛, 경남과학고 조기졸업은 유지하며 기술 섹션은 추가하지 않는다. 본문과 강조의 원본은 YAML이다. 도식·계획·예시 문장을 새로운 경력 사실로 복사하지 않는다.

## 전체 읽기 구조

본문은 제한된 읽기 폭의 한 열을 화면 가운데 배치한다. 충분한 폭에서 소개 텍스트와 사진만 나란히 놓는다. 실제 폭·글자 크기·간격은 [공유 토큰](../design/tokens.css)과 공용 스타일의 현재 값으로 확인한다. 과거 후보 범위를 합격 수치로 사용하지 않는다.

- 회사명·학교명·직무·본문의 글자 시작선을 같은 왼쪽 축에 맞춘다. 불렛 마커만 그 축 바깥의 페이지 여백에 둔다.
- 로고는 기관명 행의 오른쪽 보조 식별자다. 아래 메타데이터와 본문에 로고 전용 빈 열을 남기지 않는다.
- 짧은 항목은 짧게 끝낸다. 빈 설명행·최소 높이·넓은 패딩으로 다른 항목의 높이에 맞추지 않는다.
- 간격은 정보 관계를 드러내야 한다. 메타데이터 묶음보다 항목 경계가 명확해야 하며, 구분선·행 간격·컨테이너 패딩을 중첩하지 않는다. 마지막 섹션과 푸터의 총 여백도 함께 확인한다.

## 소개

데스크톱 읽는 순서는 이름(H1) → 역할/도메인 → 구체적인 소개 → 프로필 링크 → PDF·연락이다. 사진은 같은 영역의 오른쪽에 놓되 텍스트 폭을 지나치게 좁히지 않는다.

모바일 DOM/화면 순서는 이름 → 역할 → 소개 → 프로필 링크와 행동 → 사진이다. 한 화면에 사진까지 모두 넣으려고 정보와 글자를 압축하지 않는다. 사진과 텍스트는 공급된 비율을 유지하고, 재배치로 대응한다. 별도의 거대한 슬로건이나 같은 내용을 반복하는 강점 카드·성과 숫자 띠를 추가하지 않는다.

## 경력과 학교 근무

회사 헤더는 회사명 먼저, 로고 오른쪽이다. 회사 아래에서 직무를 강조하고 기간을 같은 줄에 가까이 둔다. 구분 기호나 공통 날짜 열을 만들지 않으며 좁은 화면에서는 자연스럽게 줄바꿈한다.

```text
회사명                                      [로고]
직무  기간

• 문제·본인 기여·지원되는 결과를 담은 첫 성과
• 두 번째 성과
• 세 번째 성과
```

복수 직무도 같은 단위를 반복하며 최신순이다. 회사명과 전체 재직기간을 다시 반복하지 않는다.

```text
회사명                                      [로고]
Data Analyst  Jul 2025–Oct 2025
Data Analyst Intern  Apr 2025–Jul 2025
```

위 공백은 역할/기간 관계를 설명하는 도식이다. 렌더링에서 두 직무의 기간 시작점을 공통 열에 강제하지 않는다. 각 직무 바로 뒤에 같은 간격으로 기간을 둔다. 직무명은 확인된 표현을 유지한다.

서비스·지역·전체 기간·단계별 기간을 헤더 여러 행에 중복 표시하지 않는다. 표시하지 않는 사실도 YAML에는 보존하지만, 다른 출력에 반드시 표시한다고 가정하지 않는다. PDF 표시 범위는 출력 설정과 인쇄 가이드가 결정한다.

학교 근무는 아래처럼 동일한 왼쪽 축을 사용하되 짧은 내용량만큼만 높이를 쓴다.

```text
학교명                                      [로고]
화학 교사, 계약직
기간
```

각 기관 로고의 다른 모양/길이가 명칭의 시작선을 바꾸지 않아야 한다. 본문에는 별도의 ‘문제·행동·성과’ 소제목을 반복하지 않으며, 읽기 단서는 [본문 강조](emphasis-guide.md)로 제공한다.

## 연구

```text
작은 회색 주제 설명
전체 원문 논문 제목 (H3)
학술지/학회 공식 전체 명칭 · 연도 · 본인 역할
논문 링크

• 연구 질문·데이터·범위
• 본인이 개발·구축한 방법이나 평가 인프라
• 검증 결과 또는 추적·재현성을 확보한 방식
```

제목과 본문은 같은 충분한 읽기 폭을 사용한다. 전체 제목을 좁은 메타데이터 열에 가두거나 불렛을 세 개의 좁은 카드로 나누지 않는다. 긴 제목을 줄바꿈하기 위해 임의로 약칭·요약하지 않는다. 논문 링크에는 어느 논문인지 식별할 수 있는 접근 가능한 이름을 둔다. 공식 명칭과 도메인 용어의 구분은 [콘텐츠 가이드](content-guide.md)를 따른다.

## 학력·수상 및 어학

학력은 학교명(오른쪽 로고) → 전공/학위·상태 → 기간으로 묶는다. 수료·학위 취득·예정을 정확히 구분한다. 수상은 명칭·주최/범위·일자를 함께 표시하고, 설명이 비어 있으면 행도 만들지 않는다. 어학 점수와 취득/만료 정보도 하나의 항목으로 묶는다. 장식 아이콘·번호가 텍스트 정렬이나 불필요한 높이를 만들지 않게 한다.

## 탐색과 출력

상단의 섹션·언어·테마 조작은 본문 읽기를 돕는 도구다. 섹션 메뉴와 테마 메뉴는 [공통 컨트롤 규칙](design-guide.md#controls-are-behavior-as-well-as-appearance)을 따른다. 모바일에서는 이름·현재 조작 상태·언어 전환이 화면 밖으로 밀리지 않아야 한다. 고정 헤더가 앵커 제목이나 키보드 포커스를 가리지 않는지 확인한다.

웹의 모던한 표현과 제출용 PDF의 포멀한 표현을 구분한다. 일반 프로필 PDF는 [현재 인쇄 명세](print-guide.md)에 따라 선택·정렬·타이포그래피만 바꾸며, 선택된 문장을 요약하거나 대체하지 않는다. 웹 정렬을 PDF에 그대로 강제하거나 반대로 PDF의 오른쪽 날짜 열을 웹에 옮기지 않는다.

## 검토와 근거

[평가 기준](evaluation-rubric.md)과 [반응형 표본](responsive-guide.md)으로 실제 화면을 확인하고, 관찰 → 위치/근거 → 영향 → 수정 → 재검증을 비공개 리뷰에 기록한다. 같은 사실/문장의 재사용, 긴 기관명·논문명, 로고 아래 여백, 불렛 텍스트 축, 메뉴 동작과 로딩 상태를 함께 본다. 이전 시안의 합산 점수나 단순 overflow 0으로 현재 결함을 상쇄하지 않는다.
