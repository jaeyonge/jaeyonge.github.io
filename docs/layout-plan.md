# 목적과 읽기 흐름에 따른 개인 프로필 화면 계획

작성: 2026-10-18. 상태: 초안 자체 검토를 반영한 계획 수정본. 화면 구현·실측 합격·독립 사용자 평가·배포를 완료했다는 뜻이 아니다. 과거 시안이나 과거 점수에 대한 선호 없이 독자의 질문과 디자인 원칙에서 출발한다.

## 1. 독자의 질문과 중심 메시지

페이지는 다음 질문에 순서대로 답한다.

1. 누구이며 어떤 분야의 일을 맡길 수 있는가?
2. 실제로 무엇을 판단하고 만들었으며 어떤 결과가 있었는가?
3. 어느 조직에서 언제 어떤 역할로 일했는가?
4. 연구에서 무엇을 다루고 본인이 무엇을 기여했는가?
5. 학력·수상·어학 정보와 이를 확인할 링크는 어디에 있는가?
6. 연락하거나 PDF를 가져가려면 무엇을 누르면 되는가?

중심 메시지: **비즈니스 문제를 이해하고, 코드·쿼리·데이터로 원인을 검증하며, 검증한 해결 방법을 재사용 가능한 기준과 자동화로 만드는 데이터 분석가.** 이 메시지는 소개에서 짧게 제시하고 경력/연구의 사실로 뒷받침한다. 모든 경력을 억지로 같은 성공 서사로 다시 쓰거나 연구 결과 전체를 개인 성과로 귀속하지 않는다.

콘텐츠 순서: 소개 → 경력(학교 근무 포함) → 연구 → 학력 → 수상 및 어학. 회사별 세 성과, 연구별 세 불렛, 경남과학고 조기졸업은 유지한다. 기술 섹션은 추가하지 않는다.

## 2. 전체 화면의 기본 구조

본문 중심의 한 열을 기본으로 삼는다. 나란히 보는 편익이 분명한 소개의 사진/텍스트만 충분한 폭에서 두 열을 허용한다. 본문을 무조건 화면 끝까지 넓히지 않으며, 읽기 폭을 제한하면서 전체 콘텐츠 영역을 화면 가운데 놓는다.

- 페이지 외곽: 콘텐츠 폭과 좌우 여백을 일관되게 유지한다. 본문 시작 후보는 약620–720px 읽기 폭이며 실제 한영 글꼴로 조정한다.
- 회사/연구의 긴 설명은 같은 본문 읽기 폭을 쓴다. 로고·날짜·번호를 위해 본문 옆에 별도 세로 열을 예약하지 않는다.
- 정렬은 정보 종류별로 정의한다. 섹션 제목/기관 블록/본문의 바깥 경계를 맞추되, 기관 헤더 내부의 로고·텍스트 정렬을 본문까지 강제하지 않는다. 불렛의 작은 마커 들여쓰기는 허용한다.
- 높이를 맞추기 위한 빈 카드/빈 설명행/최소 높이를 만들지 않는다. 내용이 짧으면 해당 항목도 짧게 끝난다.
- 세로 간격의 출발점: 같은 메타데이터 안4–8px, 불렛 사이12–16px, 기관 사이28–36px, 섹션 사이40–56px. 최종값은 실물 검토로 결정한다. 가장 큰 간격은 관련 없는 그룹 사이에 둔다.
- 구분선은 필요한 큰 그룹 경계에만 쓴다. 모든 불렛에 테두리와 넓은 패딩을 중첩하지 않는다.

이 숫자는 프로젝트의 설계 후보이며 웹 표준 합격 수치가 아니다. 글꼴·언어·실제 줄바꿈에 맞춰 조정해야 한다.

| ----------------------------- | ------------------------------- | -------------------------------------------------------------------------------------------------------------- |

기본안에는 별도 대표 사례 카드, 강점 아이콘 열, 큰 성과 숫자 띠, 일반적인 섹션 설명문을 넣지 않는다. 핵심 사례는 경력의 첫 불렛에서 바로 읽게 한다. 나중에 요소를 추가하려면 기존 정보로 충족하지 못하는 독자의 질문과 새 탐색 기능을 설명해야 한다. 이 배제는 영구 금지나 보편적 원칙이 아니라 이번 목적에 대한 구성 선택이다.

## 4. 소개

데스크톱 읽는 순서: 이름(H1) → 역할/도메인 → 강점을 설명하는 짧은 소개 → 프로필 링크/연락/PDF. 사진은 같은 영역의 옆에 배치한다. 소개 텍스트에 충분한 폭이 나오지 않으면 사진을 아래로 보낸다.

모바일 DOM/화면 순서: 이름 → 역할 → 소개 → 프로필 링크 및 연락/PDF → 사진. 특정 기기에서 화면 하나에 사진까지 전부 넣는 것을 목표로 삼지 않는다. 첫 화면에서 핵심 메시지와 행동이 사진 때문에 밀려나는지 확인한다. 이 계획으로 구현할 때 기존 responsive/design 가이드의 모바일 사진 순서도 함께 갱신해야 한다.

후보 소개 내용은 사실 검토 후 양쪽 언어를 YAML에서 함께 편집한다. 계획 문서의 문장을 바로 경력 사실의 새 원본으로 쓰지 않는다. 이름이 가장 중요한 식별자이며 소개 문장은 이름과 경쟁하는 거대한 광고 카피로 표현하지 않는다.

## 5. 경력과 학교 근무

회사 블록의 읽는 구조:

```text
[작은 로고] 회사명
            직무 · 기간 · 지역
            서비스 맥락 (이해에 필요할 때만)

• 핵심 기여를 담은 문장. 범위·방법·결과와 필요한 한정 설명.
• 두 번째 기여와 근거.
• 세 번째 기여와 근거.
```

- 로고는 헤더 로컬 그리드에만 속한다. 본문 불렛은 회사 블록 바깥 경계부터 읽기 폭을 사용한다. 로고 아래 공간을 본문 높이 전체에서 예약하지 않는다.
- 로고 슬롯 후보: 원형 문장32–40px, 워드마크64–88px 이내/높이약32px. 원래 비율과 색을 유지한다. 작은 식별자에서 읽기 어려운 글자는 옆의 회사명으로 보완하며 로고를 과도하게 키우지 않는다.
- 회사명과 직무·기간은 같은 텍스트 축에 놓는다. 메타데이터는 자연스럽게 줄바꿈하고 날짜를 화면의 먼 오른쪽 끝에 고정하지 않는다. 장기/인턴 구분은 관련 메타데이터 바로 아래 작은 문장으로 유지한다.
- 불렛은 세 개다. 기존 사실 문장을 우선 보존하고 같은 의미의 독립 제목/‘문제·행동·성과’ 라벨을 덧붙이지 않는다. 짧은 기여 구절을 문장 안에서 강조해 훑기와 연속 읽기를 함께 지원한다.
- 불렛 전체를 굵게 만들거나 검증되지 않은 숫자/인과를 크게 띄우지 않는다. 중복 집계와 실제 고객 결제, 목표와 실측, %와%p를 구분한다.

학교 근무는 내용량에 맞게 더 간결하게 표시한다.

```text
[문장] 학교명
       화학 교사 · 계약직 · 기간
```

줄이 길면 기간만 같은 텍스트 축의 다음 줄로 내려간다. 두 학교의 이름·직무·기간은 동일한 헤더 내부 규칙을 사용한다. 짧은 경력에 다른 회사만큼의 빈 행/카드 높이를 부여하지 않는다. 학교와 회사의 설명량이 다르므로 두 그룹의 모든 내부 기준선을 억지로 같게 만들지 않는다.

## 6. 연구

논문마다 다음 순서를 쓴다.

```text
작은 회색 주제 설명
전체 원문 논문 제목 (H3)
학술지/학회 · 연도 · 본인 역할 · 논문 링크

• 연구 질문/사용 데이터/범위
• 본인이 개발·구축한 방법 또는 평가 인프라
• 검증 결과 또는 추적·재현성을 확보한 방식
```

제목과 설명은 같은 읽기 폭에서 이어진다. 전체 원문 제목을 좁은 메타데이터 열에 가두지 않고, 긴 설명을 세 개의 좁은 카드로 분할하지 않는다. 세 불렛을 유지하되 별도의 세 소제목으로 반복하지 않는다. 제목과 불렛의 관계는 근접성과 적절한 간격으로 표시한다.

두 논문은 개별 연구 항목으로 분리한다. 서로 다른 데이터/방법/개인 역할을 정확히 설명하고, 전체 연구 결과를 개인에게 귀속하지 않는다. 논문 링크는 제목/발표 정보와 가까이 두고 키보드/스크린리더에서 어떤 논문의 링크인지 알 수 있게 이름을 보완한다.

## 7. 학력·수상 및 어학

학력은 학교명 → 전공/학위·상태 → 기간의 가까운 묶음. 수료를 학위 취득/예정으로 보이게 하지 않는다. 경남과학고 조기졸업과 기간을 보존한다. 로고는 해당 헤더에서만 사용한다.

수상은 수상명·주최/범위·일자를 같은 항목에 둔다. 토스 커뮤니티×OpenAI 사내 해커톤이라는 범위를 제목 또는 바로 가까운 설명에서 드러낸다. 설명이 필요 없는 항목은 한두 줄로 끝난다. 어학은 점수와 취득/만료 정보를 함께 표시한다. 일자 정렬을 위해 설명과 멀리 떨어진 열을 만들지 않는다.

## 8. 타이포그래피·색·동작·접근

- Inter/Noto Sans KR, 기존 라이선스/자체 호스팅 유지. 본문16–18px, 행간약1.6–1.8을 출발점으로 한다. 영문60–85자 정도의 실제 줄 길이, 한국어 어절/복합어와 자연스러운 구문 경계를 확인한다. 마지막 짧은 줄 때문에 제목을 줄이거나 논문명을 생략하지 않는다.
- 제목 계층은 이름H1 → 섹션H2 → 회사/논문/학교 등 항목H3. 불렛 안 강조는 별도 제목 단계가 아니다. 픽셀 크기 종류를 임의의 숫자로 제한하지 않되 중요한 단계가 구분돼야 한다.
- 색은 실제 링크/행동/포커스에 우선 사용한다. 라이트/다크 모두 일반 텍스트4.5:1, 큰 텍스트3:1 이상의 대비를 검증한다. 큰 텍스트의 정의는 WCAG 기준에 따른다. 다크모드 PDF 버튼도 예외가 아니다.
- 모바일 섹션 이동은 실제 앵커 링크를 가진 details/summary 방식 등을 검토한다. 언어/테마 조작은 계속 접근 가능하고 메뉴가 닫혀도 본문을 가리지 않는다. 화면 밖으로 밀린 메뉴를 가로 넘침 숨김으로 덮지 않는다.
- 작은 hover/focus 상태 변화만 사용한다. essential content는 JS/스크롤 애니메이션이 실행돼야 보이는 상태가 아니어야 한다. reduced-motion, 포커스, 고정 헤더의 앵커 가림을 확인한다.
- 언어 선택 우선순위, 글꼴 늦은 교체 방지, 공개 빌드의 authoring UI 차단은 유지한다. 자료/개인 메모는 sources에 두고 공개 자산 경로만 렌더링한다.

## 9. 초안 검토와 반영한 수정

| 검토에서 발견한 위험                                            | 최종 반영                                                                     |
| --------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| '같은 시작선'을 과하게 적용해 본문에 로고 공간을 강제할 수 있음 | 전역 바깥 경계와 헤더 내부 그리드를 분리. 본문 로고 열0                       |
| 모바일 쌓기만 정의하면 사진이 소개/행동을 밀어낼 수 있음        | 핵심 정보/행동을 먼저 놓는 순서 명시                                          |
| 제목 추가로 스캔을 돕다가 내용을 중복할 수 있음                 | 독립 성과 제목 대신 같은 문장 안의 짧은 강조                                  |
| 한 열이라는 말만으로 연구 제목/본문 가독성을 보장할 수 없음     | 전체 원문 제목과 본문 모두 충분한 읽기 폭, 세 불렛을 세 좁은 열로 나누지 않음 |
| 읽기 폭 숫자를 언어 공통 합격선으로 오인할 수 있음              | 범위는 시작 후보로만 기록, 실제 한영 줄바꿈으로 조정                          |
| 날짜의 정렬이 정보 묶음을 깨뜨릴 수 있음                        | 날짜를 해당 이름/직무 근처에서 자연스럽게 줄바꿈                              |
| 짧은 페이지 자체를 목표로 정보/글자 크기를 줄일 수 있음         | 사실 누락 없이 반복/간격/장식의 역할을 검토. 높이는 진단값                    |
| 원칙에 맞게 쓴 계획을 실제 화면 합격으로 주장할 수 있음         | 아래 구현 검증을 별도 완료 조건으로 둠                                        |

이 수정본은 원칙과의 논리적 충돌을 줄인 설계 가설이다. 실제 화면의 성공은 아직 검증되지 않았다.

## 10. 구현 단계의 완료 조건

합산 점수로 결함을 상쇄하지 않는다. 다음을 각각 확인하고 관찰 근거를 남긴다.

1. **사실/접근성 필수 조건:** 한영 사실과섹션 누락0, 회사·연구별세 불렛, 필수 학교/논문 링크/수료/사내 수상 범위 유지. 일반/큰 글자 대비, 키보드 동작/포커스, 320px 재배치, 실제 확대에서 핵심 정보 손실/겹침 없음. 단순 overflow0만으로 합격시키지 않음.
2. **정보 관계:** 모든 회사·학교에서 이름/직무/기간이 하나의 묶음으로 읽힘. 긴 기관명과 영어 역할이 다음 항목에 붙지 않음. 날짜를 찾기 위해 무관한 먼 열을 따라갈 필요가 없는지 확인.
3. **여백의 기능:** 로고를 숨겨도 본문의 시작점/너비가 변하지 않아야 함(헤더 내부는 예외). 로고용 빈 열이 불렛 아래까지 이어지지 않음. 빈 설명/높이 맞춤 구조 없음. 각 큰 간격은 그룹 경계라는 설명이 가능해야 함.
4. **스캔과 읽기:** 회사별 세 기여를 훑어 찾을 수 있고, 하나의 기여를 읽을 때 독립 요약→동일 본문을 다시 읽도록 강요하지 않음. 논문의 질문/본인 방법/검증을 세 불렛에서 식별 가능. 실제 독자에게 과제를 주지 않았다면 이해 속도/성능이 좋아졌다고 주장하지 않음.
5. **표본:** 320×568, 390×844와가로844×390, 768×1024, 820×1180, 1024×768, 1180×820, 1440×1000. 양쪽 언어/테마, 긴 회사명/논문 제목, 실제 글꼴/실패 대체/JS 없음, 확대/키보드를 확인. 폰트/사진 때문에 최초 페인트 이후 배치가 불안정해지지 않는지 점검.
6. **PDF:** 같은 YAML에서 두 언어를 생성하고 전체 페이지의 읽기/잘림/제목 고립/본문 연결을 확인. 웹의 사진/장식/네비게이션을 PDF에 그대로 옮기지 않음.
7. **프로젝트 검사:** content:check, assets:check, test, build, test:e2e와 실물 검토. 기존 시안을 강제하는 정렬 테스트/디자인 가이드는 새 정보 구조에 맞게 갱신. sources/reviews에 관찰→영향→수정→재검증 기록. 푸시는 별도 명시 지시 후에만 수행.

처음 구현은 구조/글자/간격/실제 콘텐츠에 집중한 로컬 버전으로 만든다. 대표 화면에서 드러난 문제를 고친 다음 모션·미세한 장식을 검토한다. 로고/사진/날짜/불렛 중 하나를 크게 키우거나 줄여 다른 구조의 결함을 덮지 않는다.

## 근거와 적용의 경계

- [NN/g 근접성](https://www.nngroup.com/articles/gestalt-proximity/): 관계 있는 정보의 근접/그룹 간 구분.
- [NN/g 시각적 위계](https://www.nngroup.com/articles/visual-hierarchy-ux-definition/): 중요도에 맞는 시선 유도.
- [USWDS 타이포그래피](https://designsystem.digital.gov/components/typography/): 읽기 폭·행간·글꼴을 함께 고려.
- [GOV.UK Summary list](https://design-system.service.gov.uk/components/summary-list/): 정보의 성격에 맞는 구조 선택. 회사/연구 설명을 key/value 목록으로 강제하는 근거가 아님.
- [W3C Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html), [대비](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html): 작은 화면과 실제 색 조합의 접근성 검증.
- OpenDesign Apple-inspired 디자인/웹 가이드: 2026-10-18 latest/applied 78d5637cb49da07e81314d1544b5fc6d37c95084 확인. 절제된 색/타이포/반응형/포커스/모션을 참고하며 대형 제품 마케팅 구성이나 여백을 자동 이식하지 않는다.

위 원칙은 이 계획의 구체적 열 수·간격·폰트 크기나 사용자 선호를 보증하지 않는다. 그것들은 이 페이지의 목적에 맞춰 검증할 구현 선택이다.

## 2026-10-18 소유자 배치 명확화

로고는 기관명과 같은 한 줄에서만 공간을 차지한다. 회사·학교·학력 모두 직무/전공·기간·서비스 설명은 로고가 끝난 다음 줄에서 블록의 왼쪽 끝부터 시작한다. 기관명 텍스트 축에 계속 들여쓰는 것을 금지한다. 위 초안 도식에서 보인 메타데이터 들여쓰기는 이 명확화로 대체된다. 본문뿐 아니라 헤더의 메타데이터에도 로고 전용 빈 열을 남기지 않는다.

## 2026-10-18 정렬·정보량 명확화

기관 로고는 명칭 행의 오른쪽에 배치한다. 회사명·직무/기간·본문의 글자 시작선을 왼쪽에 맞추고 불렛 마커만 그 선 바깥에 둔다. 두잇은 기존 상세 데이터의 인턴/분석가 기간을 한 번 표시하고 전체 기간·직무·단계별 기간을 중복 표시하지 않는다. 서비스·지역을 별도 웹 헤더 행으로 반복하지 않으며 원본 데이터/PDF에는 보존한다. 이전 왼쪽 로고 도식보다 이 결정이 우선한다.
